# CS Belajar — Inclusive Learning App

**UI/UX DESIGN** | **MOBILE APPLICATION** | **FIGMA ‧ UCD**

CS Belajar is a mobile learning application concept designed to support general students and students with special educational needs. The project explores an interactive and inclusive learning experience through multimedia learning, gamified activities, focus management, and simplified interfaces for different user needs.

## 01. Project Overview

### Project Description

CS Belajar, short for *Close Security Belajar*, is an educational mobile application concept developed as part of a Student Creativity Program in the field of Constructive Creation (PKM-KC).

The concept aims to address common learning challenges, including digital distractions, limited learning motivation, and accessibility barriers experienced by students with special educational needs.

The UI/UX design focuses on organizing learning activities into an accessible mobile experience, with different interface approaches for general students and students in Special Schools (SLB).

### Problem Statement

The project proposal identifies several challenges in digital learning:

- **Digital Distractions:** Notifications and social media can interrupt students during study sessions.
- **Learning Motivation:** Conventional learning experiences may feel monotonous and reduce engagement.
- **Time Management:** Students may need support in structuring focused study sessions and breaks.
- **Accessibility Barriers:** Students with special educational needs may encounter interfaces that are difficult to navigate.
- **Different Learning Needs:** A single interface approach may not accommodate every student's preferred way of interacting with learning materials.

The proposal also reports a survey of 167 students. Video was selected as a helpful learning medium by 89.6% of respondents, while 81.2% reported difficulty concentrating due to social media distractions.

### Objectives

- Design a more focused and interactive mobile learning experience.
- Organize learning materials and activities into clear navigation flows.
- Explore a focus-management interface to support structured study sessions.
- Design differentiated interfaces for general students and students with special educational needs.
- Consider accessibility through simplified navigation, larger interface elements, and assistive technology support.

### Design Approach

The project concept combines interactive learning design, focus management, and inclusive interface exploration.

The design process described in the proposal includes the following stages:

1. **Secondary Research** — Review relevant literature and gather information about student learning preferences, digital distractions, and accessibility needs.
2. **Technical and Interface Design** — Plan the application structure, interface mockups, and accessibility considerations.
3. **Prototype Design** — Explore application screens and user flows for general students and students in SLB.
4. **Evaluation Planning** — Define usability, functionality, performance, and user acceptance as evaluation areas.

### Key Features

**1. Learning Dashboard**

A central interface for accessing learning content and activities.

**2. Interactive Learning Materials**

A concept for organizing multimedia learning experiences, including text, images, audio, video, and game-based quizzes.

**3. Mode Security**

A focus-management concept that organizes study sessions and breaks, with configurable durations intended to help students minimize digital distractions.

**4. General Student Experience**

A more comprehensive interface concept for accessing learning activities, content, and application features.

**5. Inclusive SLB Experience**

A simplified interface concept with fewer navigation choices, larger interface elements, and accessibility considerations for students with special educational needs.

**6. Assistive Technology Considerations**

The proposal identifies TalkBack and assistive interaction as important accessibility considerations, particularly for students with visual impairments.

### Design Scope

The documented prototype concepts include:

- Welcome screen.
- Registration and login screens.
- Student dashboard.
- Learning content and activity screens.
- Chat interface.
- Mode Security screens.
- Separate learning interface flows for general students and students in SLB.

### Project Outcomes

The proposal documents mobile interface concepts and prototype flows for the CS Belajar application. These materials provide a foundation for exploring learning navigation, study-session management, and differentiated interface experiences.

**Project scope:** This portfolio focuses on UI/UX design, interface structure, and prototyping. Application implementation, functional behavior, and usability outcomes should only be claimed when supported by the actual project artifacts and evaluation records.

### Insights

The project highlights several design opportunities:

- **Focus-oriented interaction:** Study sessions and breaks can be presented through a dedicated interface rather than mixed with unrelated activities.
- **Visual learning:** Multimedia content and game-based activities can provide alternatives to text-only learning.
- **Simplified navigation:** Reducing interface complexity can make learning flows easier to understand.
- **Inclusive interaction:** Different interface needs should be considered when designing learning experiences for diverse students.
- **Personalized learning:** Learning experiences can be organized to accommodate different preferences and requirements.

These insights are derived from the project's stated objectives and design concepts, rather than verified post-launch results.

### Usefulness

The design concept provides a structured way to explore learning activities, manage study sessions, and consider accessibility within a single mobile learning experience.

It also illustrates how different interface requirements can be addressed through differentiated navigation and screen layouts.

### Practical Application

The proposed design can serve as a reference for developing an inclusive educational application, planning student learning flows, and evaluating interface concepts before implementation.

Further usability testing with representative users, including students with relevant accessibility needs, would be necessary to validate the design's effectiveness.
